## 3. 阶段 C 的正确执行顺序

### 3.1 类型图例

- **只读核验**：不改任何云端状态，失败无副作用。
- **可回滚变更**：能删掉/改回来，成本低。
- **持续影响**：一旦生效会持续存在（如集合权限、环境变量、部署版本），需要更谨慎。
- **需你先授权/决定**：DS 不能自己开始。

## 7. 常见错误（提前说，省一次返工）

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 新集合照抄现有集合的「所有用户可读」 | 投稿正文与 openid 对任何客户端可读 | 必须选「仅管理端可读写」，并在客户端直连验证被拒 |
| 把 `sitemap.json` 的 `disallow` 当访问控制 | 审核页仍可被直接打开 | 访问控制只认云函数 403 |
| 把「索引草稿 8 条」写成「已建 8 条」 | 上线后查询变慢、误判已完成 | 只认控制台截图 |
| 给 `submit` 配 `ADMIN_OPENIDS` | 以为配了就授权了 | `submit` 不读该变量；它只认 `UGC_LOG_SALT` 与业务校验 |
| 用真实用户内容做内容安全测试 | 合规风险 | 只用测试样本 |
| 把本地模拟测试当云端验证 | 汇报失真 | 两套测试必须分开表述 |
| 部署前删了 `UGC_LOG_SALT` | 所有提交 500、无记录 | 先配变量再部署，或部署后先验 C1-v |
| 直接对公众灰度 | 越过 B1/B2/B6 | 联调只在管理员/体验版范围 |
