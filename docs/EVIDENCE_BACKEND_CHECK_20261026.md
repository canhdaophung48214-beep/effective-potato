## 二、关键判读（避免误判）

1. **「接口设置」页不显示内容安全接口 ≠ 不可用。**
   该页管理的是**客户端 `wx.*` 接口**；`msgSecCheck` / `mediaCheckAsync` 属**服务端 HTTP 接口**（`/wxa/msg_sec_check`、`/wxa/media_check_async`），由云函数/服务端凭 `access_token` 调用，通常不出现在「接口权限」列表。→ 此项仍为 **「待官方后台验证」**，须查下面第 3 项。

2. **「用户生成内容场景声明 = 未声明」是已确认的合规缺口。**
   该声明的说明原文为「对小程序是否包含用户生成内容（UGC）进行使用场景说明」。任何 UGC 方案（A 或 B）上线前必须完成声明；未声明而实际存在 UGC，构成平台事实性不符。

3. **AppSecret 未生成**：服务端接口（含内容安全）需凭 `access_token` 调用，而 `access_token` 需 AppSecret 换取。→ 若走内容安全路线，需要生成 AppSecret 并**妥善保管**（不写入代码库、不截图外传；云函数用环境变量/云开发内置凭据）。

4. **IP 白名单为空**：若后续配置 AppSecret 并走服务端调用，建议同时配置云函数出口 IP 白名单（可选加固，非当前阻塞）。

## 八、官方文档取证：`framework/operation.html`（2026-10-26 实抓）

### 8.1 用户安全解决方案（= 安全风控，非内容审核）

- 定位：原文「开放 API 方式向开发者提供**安全风控接口**协助开发者应对…恶意注册、营销作弊等黑产风险」。
- 覆盖：营销作弊（刷单/虚假交易/骗补贴）、恶意注册（机器批量注册/垃圾小号/伪造身份）。
- 风险等级处置：「0 无风险，不做任何阻拦」「1–2 建议进行简单的验证」「3 中度可疑…」「4 高度可疑：建议根据业务逻辑直接拦截」。
- **开通方式（原文）**：「登录小程序，在【开发→开发管理→安全中心→用户风控→安全风控接口】申请开通即可。」
- 对应接口：`getuserriskrank`（服务端 API）。
- **与内容安全无关**：后台截图里「安全风控接口（接口开通）」按钮属这一项，**不能**据此推断内容安全接口权限。

### 8.2 内容安全解决方案（官方原文要点）

- 能力：「文本审核接口能够识别文本信息中的色情、时政违规、暴恐等违法有害内容」；「提供图片内容的智能审核服务」；「识别音频中的涉黄、涉政、谩骂等违规内容」。
- 定位：原文「平台开放 API 方式向开发者提供内容安全解决方案…**将小程序 UGC 内容接入内容安全服务，可以有效缓解人工审核、降低违规风险**」。
- **强调不充分**：FAQ 标题原文「**1、请不要完全依赖内容安全服务**」；「接入内容安全服务并不意味着一劳永逸解决所有问题」。
- **人工审核要求**：「API 判断为 REVIEW 的内容，说明可能存在风险，**需要人工确认**」；「API 判断为 PASS 的内容…**可以按照一定比例抽查**」；「我们仍建议在一些环节设置**人工审核确认**，以弥补 AI 算法存在的一些不足」。
- **本页未给出**内容安全接口的开通步骤（只给风控接口开通路径）；也未出现「强制」字样。

### 8.3 与运营规范的组合结论

| 来源 | 性质 | 结论 |
|---|---|---|
| 运营规范 5.18 / 10.2 / 10.4 | **平台明确要求** | 有 UGC 就必须调用内容安全检测接口 + 建立过滤机制 + 运营者承担主要责任 |
| operation.html 内容安全解决方案 | **建议性做法**（不标强制） | 接入后仍须人工确认 REVIEW、抽查 PASS；不得完全依赖 |
| operation.html 用户安全解决方案 | 可选风控能力 | 与内容审核无关；开通入口为「安全中心→用户风控」 |

**落地口径（供方案引用）**：MVP 的审核流必须是「接口检测 → PASS/REVIEW/RISK + 人工复核」双轨，并保留抽查记录；不能只依赖接口返回 PASS 就直接放行展示。
