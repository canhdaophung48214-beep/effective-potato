## 八、想请审查方重点看的四件事

1. **「三选一 / 小份大份拆两条」这种拆法对不对**：现在等于「一道菜 = 一个价格 = 一条记录」，会让菜品数量膨胀（2F 的 285 行里约 1/4 是多规格）。有没有更合适的建模方式（比如 `priceOptions[]`）？
2. **套餐与加料长期不录是否可接受**：真实菜单里套餐占比高（黄焖鸡 14 个套餐、米线 7 个套餐、西雅苏 7 个套餐），跳过它们会让「推荐」失真。
3. **23 家未采集要不要补**：补 = 名册覆盖 37/37（成本约 1 天）；不补 = 2F 名册覆盖率 ~38%。
4. **回滚降级是否可接受**：不引入事务（离线无法验证），只做逐条复核 + 可续删；是否值得为一个「每批次约 100–300 条、一次性导入」的场景去研究事务。
