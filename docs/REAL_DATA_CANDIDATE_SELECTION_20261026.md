## 6. 直接回答七个问题

**1. 一共有多少个候选真实批次？**
**6 个**（B1、B3a、B3b、B3c、B4、B5）。`pilot-data.js` 是 B1 的云端副本，不单列；`data/` 是演示数据，不算候选。

**2. 哪些最接近准入？**
- **B3c**：只差 1 张楼层照；门头+菜单已同框，且是唯一能看到店名的批次。
- **B1**：只差 2 张（门头 + 楼层）；但它是唯一"导入器已通过 + 云端副本已存在"的批次。

**3. 推荐优先推进哪一批？**
**先 B1，理由不是"韩小面最好"，而是"它是唯一一条路已经铺到云端"**：`pilot-data.js` 与 `batch1_min` 12/12 同构、`seed`/`submit` 已本地验证、导入器 exit 0。补 2 张照片后，可以立即走"导入 → 预演 → 写入"全链路，最快拿到端到端证据。

**4. 不选韩小面，替代是谁？**
**B3c（c03 卤大姨 8 条）**。它只差 1 张照片，是最省补拍的一批；代价是多一次命名空间批准、需要把 c03 从 batch1 拆出来、需要重生成 `pilot-data.js`。

**5. 每批最少还缺什么？**
| 批次 | 最少缺 |
|---|---|
| B1 | 门头照 1 张 + 楼层照 1 张（或书面确认 1 次） |
| B3c | 楼层照 1 张 + 命名空间批准 + 把现有门头照落到 `c03_sign.jpg` |
| B3b | 门头 1 张 + 楼层 1 张 + 拆批 |
| B3a | 5 张照片 + 与 c01 冻结映射的关系说明 |
| B4 / B5 | 生成 CSV（并核对档口编号） |

**6. 哪些需要负责人审批，哪些需要补采集？**
- 审批：①是否接受"书面确认"替代门头/楼层照片；②c03 命名空间是否批准；③优先选 B1 还是 B3c；④是否立项把 2F 转录生成 CSV。
- 补采集：B1 两张（门头/楼层）、B3c 一张（楼层）、B3b 两张、B3a 五张。

**7. 达到什么条件才能进入本地导入 / 云端预演 / 云端写入？**
- **本地导入**：`import_data.js --dir <批次> --require-evidence` **exit 0** 且 0 拒绝；证据文件全部存在；ID 通过 `check_id_admission.js`（或该批次不在其检查范围）。
- **云端预演（只读 smoke）**：选定批次后，先用 `submit`/`review` 走一次本地模拟 + 一次真实只读调用（不写集合）。
- **云端写入**：需另行授权，且同时满足：批次证据齐全、ID 批准、线上 seed 版本已确认、写入前快照方案已确认、回滚边界已确认。

D1 决定（接受书面确认？）────────┐

2. 按选择补照片（B1 2 张 / B3c 1 张）。

可并行：c03 的审批与拍照、2F CSV 立项讨论，与 B1 的补拍互不阻塞。
