### 2.1 云开发 → 数据库

1. 创建集合 `submissions`（权限：**仅管理端可读写**；不得选「所有用户可读」，现有业务集合的历史状态不可复制）。
2. 创建集合 `upload_logs`（权限：**仅管理端可读写**；云函数只 add）。
3. 建索引。**先看清"代码声明"与"云端已建"是两件事**：`config/cloud/*.json` 里的 `indexes` 只是草稿声明，控制台建完并截图核对后才算"已建"。
   - **联调必建 4 条**（均属 `submissions`，对应真实查询）：`status+createdAt`（待审列表）、`submitter.openid+createdAt`（限流计数）、`submitter.openid+clientToken`（唯一，幂等）、`dedupe.key+status`（非唯一，去重）。
   - **可延后 4 条**：`security.state+status`（审核端安全态筛选，当前代码未用）；`upload_logs` 的 `at`、`event+day`、`actor.openidHash+at`（管理端统计与清理任务未实现，随功能一起建）。
   - 若控制台限制索引数量，按「必建 → 可延后」顺序；**不得**把"声明了 8 条"写成"已建 8 条"。
4. 留证：每个集合的权限页、每个索引的列表页各截一张图（能看出索引名与字段），命名 `evidence/db-<collection>-<item>.png` 存入内部记录（不提交仓库）。

### 2.2 云开发 → 云函数

1. 上传并部署 `submit`、`review` 两个云函数（含 `package.json` 中的 `wx-server-sdk` 依赖安装）。
2. 为两个函数分别配置环境变量（**职责不同，不要互相复制**）：
   - `ADMIN_OPENIDS`：真实管理员 openid，逗号或分号分隔。**只配给 `review`**；`submit` 完全不读该变量——它既不因该变量放行，也不因它拒绝。未配置时 `review` 的所有动作一律 403（`reason=ADMIN_OPENIDS_NOT_CONFIGURED`），`submit` 不受影响。
   - `UGC_LOG_SALT`：32 字节随机值十六进制，**两个函数都要配**。`submit` 每个请求都读；`review` 的 `approve`/`reject`/`delete` 读。缺失时：`submit` 返回 500 `INTERNAL` 且**不写任何记录**；`review` 变更类动作 500 且不改状态（`session`/`list`/`detail` 仍可用，因为只读路径不写审计）。
   - 生成方式：本机 `openssl rand -hex 32`（或等价命令），生成后直接粘贴进控制台，**不写入任何文件、不提交仓库、不粘贴到聊天里**。
3. 核对运行环境 Node 版本与项目一致；部署后先调用 `session`（管理员）与一次非法提交各一次，确认 403/400 分支。
4. 记录部署时间、函数版本号、环境变量指纹（只记长度与首尾 4 字符，不记全值）。

| C6 | 管理员 approve | 记录变 approved、rev+1，日志 `review_approve`；**菜品数据未变化** | 查事务/更新条件与写库白名单 |
| C7 | 管理员 reject 并填理由 | 记录变 rejected，reasonCode/reasonText 落库 | 查枚举校验 |
| C8 | 用户删除请求 | payload 清空、openid 置 deleted，日志 `delete_request` | 查 delete 分支 |
