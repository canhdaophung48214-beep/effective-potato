## 三、原始行 → 独立记录的映射规则

### 3.1 判定顺序（必须按这个顺序，不可跳步）

1. **判类型**：这一行是「单品」「阶梯价」「多基底同价」「同菜多做法」「自选组合」「加料/可选项」「套餐」中的哪一种？
2. **拆行**：只有「阶梯价」「多基底同价」「同菜多做法」三种会一拆多；其余**一律一行一记录或整行不录**。
3. **定 `food_type`**：按 2F §7.2 已确认的依据（`data/dishes.js:16-23`）映射，不得按菜名主观归类。
4. **定 `source_detail`**：按 §五 模板生成，必须能回指「第几张照片 + 哪一行原文」。
5. **定资格**：按 §四 判 A / B / C，C 档**不得进入记录级草稿**。

### 3.2 八条映射规则

| 编号 | 情形 | 规则 | 已发生的实例 |
|---|---|---|---|
| **R1** | 一行一菜一价 | 1 行 = 1 记录 | 绝大多数 |
| **R2** | 阶梯价（买多便宜） | **按购买规格拆条**，每条价格独立、`dish_name` 带规格后缀 | 3F W05 肉夹馍：5 元 1 个 / 9 元 2 个 / 12 元 3 个 → 3 条 |
| **R3** | 多基底同价（米线/牛筋面/土豆粉） | **按基底拆条**，三条同价；不是套餐、不加 `comboItems`、不改 `record_type` | 2F W2-04 12 口味 × 3 基底 = 36；W2-11 11 口味 × 3 基底 = 33 |
| **R4** | 同菜多做法（炒饼/炒面/炒饭） | 若**三种做法可分别点选且同价**，拆三条；`food_type` 各自映射（`snack`/`noodle`/`rice`） | 2F W2-04 蛋炒区 13 口味 × 3 做法 = 39 |
| **R5** | 双规格分档（小份/大份、小碗/大碗） | **按规格拆条**（用户 2026-10-23 裁决：拆条）；每条独立价格、`dish_name` 带规格后缀 | 2F W2-07 小碗/大碗 → 15×2=30；W2-09 小份 15 个/大份 20 个 → 9×2=18 |
| **R6** | 自选组合（X 选 Y、任选 N 种） | **整行不录**（套餐模型未实现前不虚构成单品） | 3F W03「二荤二素任你选」12 元 |
| **R7** | 免费可选项（免费锅底、免费加面、免费续饭） | **只录主品，选项不录**；选项写进记录备注 | 3F W09 小火锅锅底三选一；2F 多处「免费加面/免费续」 |
| **R8** | 加料 / 卤味 / 饮料（有独立定价） | 与主品**分开判断**：有独立价格且是独立售卖单元才可单独成记录；属「加购项」的整行不录 | 3F W01 加料 5/2/2/2/2；W07 卤味 1.5/2；W08 小食 2–5 |

> R2/R3/R4 的共同前提：**牌面明确支持**（并列在同一价目行，或写成阶梯）。牌面不支持时降为 C 档（见 §七）。

### 3.3 命名与后缀约定（避免同名撞车）

- 拆分记录必须在 `dish_name` 里保留区分信息：
  - R2：`肉夹馍（1 个）` / `肉夹馍（2 个）` / `肉夹馍（3 个）`
  - R3：`金汤酸辣米线` / `金汤酸辣牛筋面` / `金汤酸辣土豆粉`
  - R4：`青椒蛋炒饼` / `青椒蛋炒面` / `青椒蛋炒饭`
  - R5：`招牌黑猪肉面（小碗）` / `招牌黑猪肉面（大碗）`；`大葱猪肉水饺（小份 15 个）` / `（大份 20 个）`
- 后缀只用**牌面原文已有**的规格词，不发明「小份/标准」这类词去替代看不清的档位。

> **一行写多口味时不拆**（如 W2-09 中「大葱猪肉 / 玉米猪肉 / 白菜猪肉 …」并列同一价位的 10 个口味）：按「同一价位的口味选项」处理，视为 1 条记录，风味写进备注。这条是本文的**保守假设**，已列为待裁决 **B13**；若你要求逐口味拆，W2-09 会从 18 条涨到 54 条、3F 多个档口也要同步扩大，届时再改。

## 五、统一元数据约束（可自动校验）

### 5.1 字段约束表

| 字段 | 取值规则 | 禁止 | 校验方式 |

| 备注 | 待补图组必须含 `待补证`；免费/加购项必须写明「已按 R7 不录」 | 用备注伪装成已核实 | C6 / C7 |
