## 四、A′ 持久性补丁与执行环境（2026-10-25 已落地/已验证）

**补丁（本轮已实施，测试 T242/T242b 覆盖）**：`initIdMap` 写入协议在 `linkSync` 成功后与 `unlinkSync(tmp)` 成功后**各实际执行一次父目录 `fsync`**（`fsyncDirNow`，与能力探测 `checkDirFsync` 分离——探测成功≠同步成功）；任一失败返回新状态 **`INIT_DURABILITY_UNCONFIRMED`**（IO 类/退出码 3/`wrote:true`/`phase` 区分 `afterLink`/`afterUnlink`），**保留目标与残留证据、不自动删除、不重试**。防覆盖（lstat 前置+linkSync EEXIST）、wx 独占临时文件、文件级 fsync、读回校验、Windows 探测 EPERM→`INIT_FSYNC_UNAVAILABLE` 零写入等既有行为全部保留；`initIdMap` 仍无生产调用点（普通 `gen`/`dry-run`/`write` 不获自动初始化能力，T243 断言）。

**执行环境实测（2026-10-25，WSL2 Ubuntu）**：

| 项 | 实测结果 |
|---|---|
| 根文件系统 | `/dev/sdd` **ext4**（`df -T /`）——A′ 执行环境确认 |
| `/mnt/c` | **9p**（挂载 `C:\`）——**不是原生 ext4**；其目录 fsync 调用虽返回成功，但 9p 协议对 fsync 的持久性语义**无文档保证**，不得当作 ext4 级保证使用 |
| ext4 目录 fsync | python3 `os.fsync(目录fd)` 实测 **OK**（与 Node `fs.fsyncSync` 同一 syscall） |
| WSL 内 Node | **未安装**——实施轮环境准备项（届时另行授权/负责人操作），或以其他等效方式执行 |

**A′ 执行流程（实施轮执行，本轮不执行）**：WSL ext4 内（项目副本置于 `~/`）运行初始化（完整协议：探测→wx→写入+文件级 fsync→link→目录 fsync→unlink→目录 fsync→读回）→ 校验 → 将生成的 `id-map.json` 复制回 NTFS 项目 `tools/pilot/`（复制后目标为「已存在被加载」，加载侧对持久性要求低于创建侧；复制丢失模式=文件不存在→E12→重走流程，fail-safe）→ 项目内首次 `loadMap` 验证（结构五步+审批核对）。

## 六、冻结映射 → 运行时 payload 转换规则（待负责人批准）

| 运行时字段 | 来源 | 规则 |
|---|---|---|
| `schemaVersion` / `keyFormat` | 常量 | `1` / KEY_LITERAL 逐字 |
| `key`、四字段、`dishId`、`sourceRef` | 冻结映射同名字段 | 逐字复制；与生成器候选记录 104/104 一致为前置断言 |
| `status` | **映射规则：`assigned_unverified` → `active`**（**待负责人批准的设计决策，本轮未定**） | 语义分离：`assigned_unverified` 是**分配/核实域**状态（records 层 verifyStatus 域，全体 `unverified` 不变）；运行时 `active` 若最终被批准，**仅表示映射条目处于生成器可用状态——不表示菜品已核实、来源可信或可以发布**；PK1-R1 排除 pending_review |
| `assignedAt` / `generatedAt` | 审批记录 `approvedAt`（单一时间源，保证转换可复现） | 待审批记录签发 |
| `approvedBy` | 审批记录（`user:负责人审批 ip-20261025-01`） | **禁止 auto、禁止伪造**；记录缺失→初始化侧失败（G-4=C，退出码 1） |
| `orphans` | `[]` | 首次初始化 |
| `initialization` | 审批记录 | `{approvalRef, planDigest, mapVersion}` 逐字段取自审批，不得编造 |
| （不携带）`name`/`price`/`tier` | — | 映射不承载非身份字段 |

fail-closed：条数≠104、与生成器输出缺/多/异、E13/E14 重复、审批缺失（G-4=C）、审批字段不匹配（E26）、planDigest 不一致（E25）——一律拒绝，不修剪不补不重试。

**确定性序列化（已随实施轮落地，`canonicalJsonStringify` + `buildInitPayloadFromFrozen`）**：payload 对象键按 UTF-8 字节序升序书写（`entries`→`generatedAt`→`initialization`→`keyFormat`→`orphans`→`schemaVersion`；条目键 `approvedBy`→`assignedAt`→`disambiguator`→`dishId`→`groupKey`→`key`→`sourceRef`→`specLabel`→`stallId`→`status`）；`entries` 按 `key` 的 UTF-8 字节序排序（`Buffer.compare`）；序列化 `JSON.stringify(v, null, 2) + "\n"`（UTF-8、LF、无 BOM）。同输入必得同字节（时间字段单一来源=审批 `approvedAt`，不取执行机器时钟）。

**`mapVersion` 定稿：`"1#1"`**（技术负责人 2026-10-25 已批准）——按契约 §5.6.5.8.1 表既有规则（`schemaVersion + 生成序号`）：结构版本 1 + 首次生成序号 1；与 `schemaVersion` 为不同字段（前者=映射版本代数、后者=结构版本，运行时格式不校验、由审批一致性核对承担）。计划 §十二 T-5 随此关闭。
