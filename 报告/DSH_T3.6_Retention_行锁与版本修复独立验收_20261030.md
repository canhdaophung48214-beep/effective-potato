## 5. 复审时我将执行的判据与探针（供实现方对齐）

> 这些探针在隔离副本（`%TEMP%`）运行，只读项目文件；不写项目、不触云。

### 5.1 A 行锁 / 并发（对应任务第 1、2、3 项）

1. **A1 两实例并发**：同一假库上并行调用两次 `purgePayload`；判据：`payloadRedactedAt` 只写一次、`rev` 只 +1、批次日志不重复、对账 `closed` 计数与 `purged` 一致。
2. **A2 旧实例复活**：实例 1 读到 `rev=1` 后挂起；实例 2 完成清理（`rev=2`）；实例 1 恢复并尝试写入。判据：实例 1 必须失败（`conflicts` 计数、正文不变），且不得产生"半清"状态（`payload=null` 但 `retention.purge.state` 缺失之类）。
3. **A3 租约过期**：租约到期后另一实例可接管；判据：同一记录全生命周期只有一个"成功清正文"事件，且接管方能看到前任的未完成标记并走恢复。
4. **A4 崩溃释放**：进程在"清正文后、写逐条日志前"被杀；判据：下次 `recoverPurgePending` 能凭稳定事件 ID 补齐审计，正文不回滚、不重复清。
5. **A5 锁的可见性**：锁必须是持久记录（可查、可超时接管），不能是单进程内存变量；判据：跨函数实例（两个独立 `loadFunction` 导出的 main）仍互斥。
6. **A6 反事实**：删掉锁的获取/校验任一分支，上述至少 2 条必须变红；若删掉后仍全绿，说明测试未覆盖。

### 5.2 B 版本修复（第 2 项）

1. 每次正文变更必须 `rev+1`，且返回值里可核对"我用的是哪一个 rev"；
2. 读取方（审核页/导出/对账）必须能识别"我看到的是旧 rev"，不能把旧判据套在新数据上；
3. 反事实：去掉 `rev` 条件 → A2/A3 探针必须变红。

### 5.3 C/E 精确收窄与分页锚点（第 4、6 项）

1. 起点锚点由"上次结束的 `_id` + 结束时间"共同确定；下一页从 `_id > last` 严格续扫；
2. 判据：1001 条 → 3 页，跨页无重复、无遗漏（用 `Set` 逐条比对）；中间插入"更小 `_id`"的日志必须被明确排除并写入 `scanScope`；
3. 恢复后再跑一次，`batches` 结果稳定（`replayEqual`）；
4. 反事实：把锚点换成"从头重扫"，测试必须仍然通过但页数/扫描量变化可观测（否则说明断言只看结果不看过程）。

### 5.4 D 历史异常修复（第 5 项）

1. 只对"能证明缺失"的记录补：事件 ID 稳定、内容为幂等摘要、重复调用不新增；
2. 无法重建证据的批次：保持阻断，并提供人工调查入口（不提供 force/ignore）；
3. 判据：修复事件本身可被同一 `reconcileBatches` 识别为 `closed/OK`，且总量不因修复而虚增（`validCompleteCounts` 仍守恒）。

### 5.5 F 云端能力映射（第 7 项）

1. 静态核对：事务/条件更新 API 是否支持当前查询形态（`where` 多条件 + `orderBy` + `limit`）；
2. 明确"本地假库通过 ≠ 云端原子性成立"，报告须列出未验证项（索引排序、`_id` 单调性、回执不确定、请求大小上限）；
3. 若云端不支持所需原子性，必须给出降级方案（如两阶段标记 + 事后对账）并说明残余窗口，而不是宣称已消除。

### 5.6 G 测试证据（第 8 项）

1. 新增测试必须能在"未修版本"上失败（隔离副本还原旧实现跑一遍）；
2. 变异必须指向**被声称修复的那一行**，而不是无关分支；
3. 不允许删除/弱化既有断言；新增断言需给出对应契约/设计条款。
