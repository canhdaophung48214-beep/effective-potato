三个核心判断：

1. **A 类注定极少（只有 3 条），这是检查器的构造决定，不是作者粗心。** 检查器 `namedDocKey()` 只承认「§ 之前 40 字符内紧邻出现的 `.md` 文件名」这一种行内证据；凡满足该条件的引用早已被判 `ANCHOR_OK`（1642 条），所以剩下的 77 条按定义都不可能靠"同行 .md 文件名"自救。A 类只能来自"文档名称（中文简称）+ 换行续句"这类检查器正则看不见、但人能唯一确定的证据。
2. **B 类的 20 条，人的判读是确定的，检查器的判读是盲的。** 它们分别由「2F」简称、「契约」简称、「R5 / L3 / C17」等文内编号、「契约依据」表列、「上一行显式文件名续句」等弱标识支撑。实测（§7）表明：**把这些弱标识换成完整 `.md` 文件名即可全部转为 `ANCHOR_OK`**，而只写中文简称（"契约 §3.3""2F 转录稿 §7.4"）检查器一律仍然报歧义。

## 1. 判定口径与检查器行为（先讲清"为什么只有 3 条 A 类"）

### 1.1 77 条的机械成因

`项目\tools\check_doc_refs.js` 的 `scanAnchors()` 对每个 `§(\d+(?:\.\d+)*)` 取"§ 之前 40 字符"作为 `before`，然后：

| 步骤 | 条件 | 结果 |
|---|---|---|
| ① 显式命名 | `namedDocKey(before, docs)` 命中（40 字符内含 `.md` 文件名，且排除 `:NNN`/`#` 形式） | `ANCHOR_OK` / evidence `EXPLICIT`，**共 1642 条** |
| ② 白名单 | 未命名 → 取 `tools/doc_ref_whitelist.json` 中该源文件 `allowed[]` 与"含该节号的文档集合（owners）"的交集 `cand` | `cand.length === 1` → OK |
| ③ 交集为空 | `cand.length === 0` | `ANCHOR_AMBIGUOUS` / evidence `NONE` |
| ④ 交集多个 | `cand.length > 1` | `ANCHOR_AMBIGUOUS` / evidence **`WHITELIST_MULTI`** |

**77 条全部是 ④（`WHITELIST_MULTI`），`named: null`**——即"45 个字符内没有 .md 文件名，且白名单允许的目标里有多份文档都含这个节号"。这直接推出 §0 的第 1 点结论。

### 1.2 检查器已有但未接线的能力（这是"声明方案"的技术依据）

| 位置 | 符号 | 现状 |
|---|---|---|
| `项目\tools\check_doc_refs.js:293` | `qualifierTarget(...)` | 已定义、已 `module.exports`，但 `scanAnchors()` 内**从未调用** |
| `项目\tools\check_doc_refs.js:320` | `titleHint(...)` | 同上，已定义未调用 |
| `项目\tools\check_doc_refs.js:366-368` | `if (!cls) { ... qual ... }` | 因 `cls` 在此之前必被赋值，该分支不可达；其中引用的 `qual` 变量在作用域内**未定义**，属潜伏缺陷（当前不触发） |

→ 也就是说：把"契约 §3.3"这类中文限定词解析成目标文档的函数**代码里已经写好了，只是没接进主流程**。接线的改动量很小，但属于代码变更，需授权（见 §6）。

### 1.4 三类定义（本报告口径）

- **A 类**：行内（含紧邻上下行、同一句换行续写）存在**文档文件名的中文全称或完整文件名**，且与候选集合唯一匹配 → 人的判读唯一，检查器未识别。
- **B 类**：行内只有**弱标识**——文档简称（"2F""3F""契约""方案文档"）、文内编号（R5/R1–R8、L3、C17–C20、E3）、表列名（"契约依据"）、上下文续句 → 高置信但非显式，检查器原理上无法识别。
- **C 类**：**无任何文档线索**——裸 `§X.Y`、表格单元格、测试消息串里孤立的节号。

> 注：A/B/C 是"文档归属证据强度"的单轴分类；另有一条独立的**语义维度**（章节号与断言内容是否对得上），结果单列在 §4.5 与 §5，不并入 A/B/C 计数。
