## 请求、审核、删除的三段语义

1. **请求已提交**：服务端持久化删除请求并返回 requestId；用户界面仅报告“已收到”，不改变原投稿审核结果。
2. **审核已完成**：管理员对请求作出明确决定，包含审核时间与结果；拒绝请求不能写成“数据已删除”。若产品确定无需人工审核，也须把自动核验结果作为明确审核事件记录，不能跳过该状态。
3. **数据已删除**：正文实际清空、归属信息按批准规则匿名化，读回确认并写最小审计后才能返回该状态；若日志写入失败，必须如实暴露“删除已执行但审计待补”之类可恢复状态，不假报事务回滚。

这里“增加删除请求入口”并不自动授权直接物理删除。`ugc_self` 云函数和请求状态存储属于额外技术变更，须先审查接口、状态机、权限和恢复语义；本阶段仅给方案。

## 离线验收矩阵与待授权边界

| 场景 | 预期 |
|---|---|
| 非管理员打开审核页 | 403，轮询不启动，列表和计数不泄露 |
| 管理员页面前台/后台切换 | 前台单实例轮询，后台和卸载立即停止，无重叠调用 |
| 网络失败/409 | 退避并保留人工刷新；审核动作 409 后刷新最新 rev |
| 用户 A 请求删除用户 B 的投稿 | 统一 404，不泄漏 B 的存在性 |
| 无 OPENID/伪造 OPENID | 401/忽略客户端伪字段，绝不以客户端身份授权 |
| 相同请求重试、并发请求 | 同一归属记录只有一个有效请求/删除结果，审计不重复 |
| 三段状态切换失败 | UI 不越级显示“已删除”；实际清理与审计结果可恢复核对 |
