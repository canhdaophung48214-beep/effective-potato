## 二、判定口径（可复核）

分类定义按任务书：A 有明确原始证据可恢复 / B 间接证据需负责人确认 / C 无足够证据必须保持未知 / D 存在冲突需人工裁决。落地判据写在 r01_e2_analyze.js 的 tasteOf() 与 ftOf()，顺序固定、先命中先归类。

**tastes 判据顺序**

1. 名称含「 / 」并列多变体，且其中既有辣味变体又有非辣味变体 → **D**（同一价格下口味不能定为单值）。
2. 名称含「 / 」并列多单品单价格 → **B**（组合行，需逐品拆分）。
3. 源行括注含辣度字面（（辣）/（微辣）/（不辣）/（辣度适中）/（香而不辣）/（爆辣））→ **A**，候选值按字面映射（下表）。
4. 同块存在「口味：…」或「口味（N 选一）」选项行 → **B（choice 候选，作用域需确认）**；菜品专属口味行（含「元」且含该菜名）只对该菜生效。
5. 菜名含辣味词（麻辣/香辣/酸辣/甜辣/辣/椒麻/藤椒/剁椒/泡椒/双椒/尖椒/小米辣/胡辣）→ **B**。
6. 其余 → **C**。

**A 档字面 → 枚举映射与可信度**（候选值仅供审查，未落盘）

| 牌面字面 | 候选枚举 | 可信度 | 说明 |
|---|---|---|---|
| （微辣） | mild_spicy | 高 | 与 TASTE_LABEL 逐字一致（data/index.js:40） |
| （不辣） | light | 中 | 「不辣」与 light（清淡）是近似而非同义，需负责人确认 |
| （香而不辣） | light | 中 | 描述性文字，取 light 属候选 |
| （辣度适中） | mild_spicy | 中 | 枚举无「适中」档，需确认归入微辣还是另有口径 |
| （辣） | spicy | 中 | 枚举 spicy 的标签是「麻辣」，是否等同需确认 |

**foodType 判据顺序**

1. 名称同时命中两类及以上主食词 → **D**（主食类型不唯一，需裁决）。
2. 名称命中单一主食词 → **B**（候选枚举 + 词法映射，需负责人确认映射表）。
3. 其余 → **C**（无主食词，无法判定）。

词法映射（仅用于生成候选，不作为填值依据）：麻辣烫/冒菜→malatang；米线→rice_noodle；米粉/粉丝/宽粉/土豆粉/粉→rice_vermicelli；水饺/饺子/馄饨/小笼包/烧麦/锅贴→dumpling；面（不含面包）/拉面/捞面/拌面/汤面/刀削面→noodle；盖浇饭/蛋包饭/拌饭/双拼饭/炒饭/焖饭/饭→rice；粥→other；饼/馍/馕/烧饼/火烧/包子/花卷/油条/馒头/凉皮/寿司/饭团→snack。

**四条禁令的落地方式**（任务书第三节）：

- 规则 1（不凭菜名推口味）：菜名线索一律落 B，绝不进 A；候选列写「（按菜名辣味词推测的枚举值，仅供审查）」而不给具体枚举，避免被误当结论。
- 规则 2（不把未知设为清淡/不辣/可选辣度）：C 类候选列一律写「—」；choice 仅在牌面确有「口味：A/B/…」或「口味（N 选一）」字样时作为 **B 类候选**出现，并标注作用域待确认。
- 规则 3（不凭经验推断 foodType）：foodType A=0，全部词法结果只进 B。
- 规则 4/5/6/7（不改数据、id-map、审批、契约、不写正式 CSV）：本轮零写盘，见第十一节自检。
