### 1.3 本轮最重要的技术发现

**D7 的「只许恰 1 个」不是一处判断，是三处串联判断；只改第一处达不到放宽目的。**

`tools\verify_data.js:351-357`：

```js
if (!Array.isArray(dish.tastes)) {                     // ① 非数组 → D7
} else if (dish.tastes.length !== 1) {                 // ② 长度不等于 1 → D7
} else if (TASTE_VALUES.indexOf(dish.tastes[0]) === -1) { // ③ 枚举外 → D7
}
```

- 只把 ② 改成 `length > 1`：`[]` 会落到 ③，`tastes[0] === undefined`，`indexOf(undefined) === -1` 成立 → **仍然报 D7**，只是错因文案从「长度必须是 1」变成「口味值不在 … 内」。
- 必须同时把 ③ 改成「仅当长度恰为 1 时校验枚举」：实测 `[] → D7 0 条`、`[light, spicy] → D7 1 条`、`[very_spicy] → D7 1 条`、`[light] → D7 0 条`，语义正确。
- **实测对照**（同一份 `[]` 数据）：单点放宽 → D7 = 1 条；两点放宽 → D7 = 0 条（见 §2.5 实验 E1/E2）。

因此如果有人按「只改一行」的思路申报放宽，校验器会在 0 条报错之外仍然拦下空口味 —— 这是本轮最容易踩空的地方。
