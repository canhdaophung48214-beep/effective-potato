# 食神寻味 · UI 概念设计说明（第一阶段）

> 本阶段只产出视觉概念，**没有改动任何业务代码、`app.json`、路由、云端数据、集合权限或 Git 历史**。
> 图中所有菜品、价格、评分、人数、动态均为示意，不是真实数据。

## 1. 视觉方向：灶火纸感

食堂的真实质感不是「外卖 App 的橙」也不是「点评的橙红渐变」，而是**搪瓷盘、旧木桌、菜单纸、灶火**。所以整套界面用暖纸底 + 白卡 + 极细暖灰描边，靠**红与姜黄**点火，不靠大面积渐变和阴影。

- 背景 `#FAF6F0`（纸），卡片 `#FFFFFF` + 1px `#EDE4D9` 描边，阴影只有 `0 1px 2px rgba(36,30,26,.05)`。
- 圆角统一（卡 18px / 图片 12–14px / 胶囊 999px），不用大小混杂的圆角制造「活泼」。
- 装饰极少：没有插画贴纸、没有渐变蒙版、没有渐变按钮。

## 2. 颜色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 主色（灶火红） | `#D9412B` | 主按钮、选中态、价格、分数。取自红烧肉/番茄的暗红，比平台橙更「食堂」 |
| 主色深 | `#B8321F` | 按下态、标签文字 |
| 主色浅 | `#FDECE7` | 标签底、提示底 |
| 姜黄（次色） | `#E9A038` / 底 `#FFF4E3` | 榜首、待审核、价格变化提示 |
| 玉绿（第三色） | `#2F8B6A` / 底 `#E9F6F0` | 已通过、核对通过 |
| 墨色文字 | `#241E1A` | 标题与正文主色 |
| 次文字 | `#6F655D` | 说明文字 |
| 弱文字 | `#9C9289` | 时间、单位、辅助信息 |

红为主、姜黄为辅、玉绿只用于「状态通过」，避免三色抢戏。

## 3. 字体与图标

- 字体：系统字体栈（`PingFang SC` / `Microsoft YaHei`），小程序内不加载自定义字体，保证首屏速度。
- 层级：品牌 25px/800 → 区块标题 16px/800 → 卡片标题 13–16px/700–800 → 正文 12.5px/1.65 → 辅助 9.5–11px。
- 数字用法：价格与分数用 800 字重 + 主色，是每张卡唯一的「视觉重音」。
- 图标：统一 1.7–1.9 线宽、圆端点、无填充的线性图标；底栏 22px，列表 18px。不混用面性图标。

## 4. 图片规范

- 今日推荐卡：高度 96px 的 4:3 图；榜单/档口：44–46px 方图；榜首与动态：108px 或双列。
- 所有示意图右下角固定「示意图」角标 —— **这是本次设计的硬规则**，概念图和未来真实数据都要能一眼区分「实拍 / 示意 / 无图」。
- 真实图片接入后：无图显示统一占位 + 「暂无实拍图」，加载失败保持卡片布局不塌陷（与现有 `datasetGuard` 的失败策略一致）。

## 5. 底部四栏

高 76px（含 18px 安全区内边距），四项等分：**首页｜评分｜社区｜我的**。选中项为主色实心图标 + 800 字重文字，未选中为 `#9C9289`。

- 投稿入口**不做第五栏**，放在业务位置：首页右下「＋ 添加美食」浮钮、社区右上「＋ 发布」、评分卡内「去评分」。
- 微信小程序 tabBar 最多 5 项，4 项留有余量；实际实现需在 `app.json` 配 `tabBar`，本阶段未改。

## 6. 四个栏目的定位差异

| 栏目 | 定位 | 页面结构 | 与其他栏目的区别 |
| --- | --- | --- | --- |
| 首页 | 发现：今天吃什么 | 搜索 → 分类 chip → 随机卡 → 今日推荐横滑 → 附近档口 | 唯一以「筛选 + 随机」为核心的页面，保留现有产品能力 |
| 评分 | 比较：值不值得吃 | 三档切换 → 本周榜首大卡 → 榜单行 → 打分入口 → 分数构成 | 以「分数 + 人数」为视觉重音，不做动态流 |
| 社区 | 交流：同学情报 | 分类 chip → 图文动态 → 价格情报卡 → 求助帖 | 以「人和内容」为主，图片更大、有小作者信息 |
| 我的 | 管理：我的贡献 | 资料 → 贡献统计 → 投稿四态 → 我的内容 → 帮助 | 以「状态与进度」为主，无图片流 |

## 7. 主要交互入口

- 首页：搜索条、6 个分类 chip、随机卡「随机一道」、卡片点击进详情、档口「按楼层浏览」、「＋ 添加美食」浮钮。
- 评分：综合评分/性价比/近 7 天切换、榜单行点击、「去评分」。
- 社区：分类切换、动态卡（收藏/评论/举报）、右上「＋ 发布」。
- 我的：投稿四态（待审核/已通过/需补充/已驳回）、我的评分、我的收藏、帮助与反馈。
- 全局：底栏四栏切换。

## 8. 属于「未来功能」的部分（当前代码里没有）

搜索、图片、评分与评价、社区动态/点赞/评论/举报、投稿与审核状态、收藏、微信登录与资料、四栏路由与 tabBar。

**目前小程序实际有的能力只有**：单页（`pages/index/index`）的就餐区域/预算/口味/主食类型/地点级联筛选、随机选一家、随机选一道菜、再抽一次、换一家、查看全部 + 三档价格排序、条件摘要、重置、加载/失败/重试三态、演示数据可信度标记。概念图里的四栏、图片、评分、社区、投稿都还没有实现。

## 9. 需要结合微信平台规则再确认的点

1. **UGC 合规**：评分、评价、社区动态、用户上传图片属于用户生成内容。个人主体 + 「信息查询」类目通常不能开放公开社区/评价，需主体升级（个体户/企业）或改为「编辑精选」只读展示。
2. **内容安全**：图片必须走 `security.mediaCheckAsync` 异步检测，文本走 `msgSecCheck`；未通过不得展示。
3. **审核机制**：概念图里「待审核/已通过/需补充/已驳回」四态意味着**人工审核流程**，需明确谁审、多久审、如何申诉。
4. **存储与权限**：用户上传图需要云存储目录权限与临时链接策略（方案 A 上传待审目录 / 方案 B 云函数下发，二选一）。
5. **诱导行为**：不得用「打分得奖励」等文案，评分不能与任何利益绑定。
6. **tabBar 限制**：最多 5 项、图标尺寸固定，需出 81×81 的 PNG 图标资源。
7. **真实数据边界**：概念图中所有菜品/价格/评分必须持续标注「演示」或「示意」，直到有可追溯来源并核实。

## 10. 文件与可编辑性

设计稿是可编辑的 HTML + CSS，不是一张扁平图：

```
design/ui-concept/
├─ concept.css              # 设计令牌与全部组件样式
├─ home.html                # 首页
├─ rating.html              # 评分
├─ community.html           # 社区
├─ profile.html             # 我的
├─ overview.html            # 四屏总览
├─ home-concept.png         # 750×1624
├─ rating-concept.png       # 750×1624
├─ community-concept.png    # 750×1624
├─ profile-concept.png      # 750×1624
├─ all-tabs-overview.png    # 2550×1515
└─ 设计说明.md               # 本文
```

改色只改 `concept.css` 顶部的 `:root` 变量；改文案直接改对应 HTML。重新出图：

```bat
msedge --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=2 ^
  --window-size=375,812 --screenshot=home-concept.png ^
  --user-data-dir=%TEMP%\uic home.html
```

> 注：当前机器的项目路径含中文，直接用 `file:///` 指向项目目录截图会静默失败，需先把 `design/ui-concept/` 复制到 `%TEMP%` 下的纯英文路径再渲染，然后把 PNG 拷回。

## 11. 下一阶段建议（等你选定方向后再做）

1. 你选定主色与方向（可只选颜色、也可整体采纳）。
2. 出 tabBar 四个 81×81 图标 + 页面级 WXSS 令牌（`app.wxss` 加 CSS 变量）。
3. 只做「首页 + 底栏四栏骨架」的代码改造，评分/社区/我的先做静态占位页。
4. 逐步把评分、投稿按后端能力接上，避免先做界面后补规则。
